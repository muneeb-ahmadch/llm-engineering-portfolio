Reference · Agents · Orchestration Orchestration & the deterministic check A pipeline is a sequence of stages. Some are code, some are models, and only one of those two kinds can be argued with. How to map yours, where to put a check, and what a check is actually able to decide. Compressed from Lesson 13. Made to be reread the night before an interview. The stage map: do this before you defend anything One row per stage. The two columns that matter are the last two, and most people never fill them in. Stage Code or model Reads untrusted text? An attacker can make it… retrieve / rerank code + local model yes …return their chunk. Not behave differently: similarity has no instructions to hijack. build context code yes (passes it through) …nothing, unless the format itself is forgeable, hence a per-request nonce. generate model yes …answer their way, skip a tool, refuse a question it could answer. judge / guard model yes …pass an attack, or punish the answers that resisted it. scores / gate code no (reads verdicts) …nothing directly, but it inherits whatever the stage above it decided. The one durable idea Every guard that is a model can be argued out of its verdict. Stacking a second model on top moves the target, it does not remove it, and now there are two. The only stage an attacker cannot argue with is the stage that isn’t a model. Orchestration’s real question is not “how many agents?” but which stages have to be models at all. A schema gives it fields. That is the whole reason structured output is a security control (OWASP LLM01 #2) and not just a parsing convenience. Endpoint Key Chat Completions chat.completions.create response_format: {type:"json_schema", json_schema:{name, strict:true, schema}} Responses responses.create text: {format: {type:"json_schema", strict:true, schema}} Agents SDK Agent(…) output_type=PydanticModel , “tells the model to use structured outputs instead of regular plain text” Schema rules that bite: every field must be in required , every object needs additionalProperties: false , and allOf / not / if–then–else are unsupported. The limit, verbatim “The model will always generate responses that adhere to your supplied JSON Schema” — but “ Structured Outputs can still contain mistakes ” and “the model will always try to adhere to the provided schema, which can result in hallucinations if the input is completely unrelated to the schema” ( OpenAI ). The shape is guaranteed; the values are not. So the check must decide a property of relations you control , never a property of the content the model wrote. The decidability ladder: pick the property before writing the check Check Decidable Catches Blind to Every claim carries a citation id production Uncited assertions: parametric rescue Anything the model will cite The id is in this request’s retrieved set production Invented or smuggled ids A truthful citation of a poisoned chunk The cited chunk supports the claim heuristic only Citation drift Paraphrase; has its own false-positive rate The cited chunk is not poisoned CI only Every planted injection, deterministically Production: you don’t have the poison list at runtime The trap to avoid saying out loud: “citation validation defends against prompt injection.” It does not. In an adversarial suite the poison list makes it a perfect oracle, because you wrote the poison. In production, if you knew which chunk was poisoned you would have deleted it. What rows 1–2 genuinely buy in production is a control against uncited and invented content. Injection is defended upstream, segregation, and above that corpus provenance. Guardrails as tripwires: where a check may sit @input_guardrail # runs only if this is the FIRST agent @output_guardrail # runs only if this is the LAST agent def guard(...) -> GuardrailFunctionOutput: return GuardrailFunctionOutput(output_info=..., tripwire_triggered=True) # → raises InputGuardrailTripwireTriggered / OutputGuardrailTripwireTriggered A tripwire halts the run and shows on the trace. It is a boolean, not a score, the same score-vs-tag distinction from L10, one level up. Guardrails sit at boundaries, not mid-loop . Segregate on entry, validate on exit. There is no legal place to stand between a tool result and the model reading it, which is exactly where a poisoned chunk enters. Input guardrails run in parallel with the agent by default (latency); run_in_parallel=False blocks first and spends no tokens when the tripwire fires. Cost versus safety, as a flag. Orchestration patterns: the vocabulary Pattern Shape Reach for it when Single agent + tools One loop, N tools The default. Add tools before you add agents. Agents as tools Specialist called like a function; control returns “a specialist should help with a bounded subtask but should not take over the user-facing conversation” Handoff Control transfers and stays “routing itself is part of the workflow and you want the chosen specialist to own the next part” Chaining Output of one is input to the next Decomposable work: retrieve → generate → judge Evaluator loop Generate → grade → regenerate until it passes Quality has a checkable criterion and a retry is cheaper than a wrong answer Parallel asyncio.gather over independent stages Speed, when nothing downstream depends on the others Two things worth saying in an interview: a judge is an evaluator that was never put in a loop , closing that arrow is the evaluator-optimizer pattern, and it multiplies a bill that is often already larger than generation. And a second model call is not a second agent : only the loop-back arrow changes the category. The honest interview answer “My grader was an LLM reading the same untrusted corpus as the generator, so a poisoned chunk could make it punish the answers that resisted the attack, I have the transcript. Adding a second grader would have had the same exposure, so I moved the check out of the model: structured output with per-claim citations, and a Python validator that every cited id is one I actually put in the context. It decides uncited and invented , deterministically and for free. It does not decide poisoned , that needs the poison list, which only exists in my test suite.” The weak version stops at “we validate the output.” The strong one names what the check can decide and what it can’t , which is the same move as reporting the regression next to the win.
