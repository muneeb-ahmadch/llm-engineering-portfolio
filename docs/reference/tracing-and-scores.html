Tracing answer quality

A trace shows you what happened on one request. A score is what makes whether it was any good queryable, aggregatable, and alertable across all of them. Compressed from Lesson 10. Made to be reread the night before.

The one distinction that matters

Langfuse gives a trace three places to hang information. They are not interchangeable, pick by what you need to ask later, not by what's easiest to write.

PrimitiveWhat it's forAggregates into a rate?
ScoreA graded verdict on the run: abstained, faithfulness, a thumbs-up. Numeric / boolean / categorical / text.Yes: this is the whole point. Mean over a window = a monitorable rate.
TagA coarse label to filter a trace by: prod, rag-eval, model:gpt-5.4-mini.No: filters, doesn't average. Trace-level only.
MetadataFree-form context for one trace: config, request id, corpus version.No: searchable per-trace, not summable.

Why abstention is a score

The thing you need from abstention is a rate, the band from answer-defense: too low means the model is answering things it shouldn't; too high means retrieval is starving it. A rate is a mean over many runs. Among the three primitives, only a score is averaged. A tag would tell you which traces abstained but never what fraction; metadata wouldn't even filter cleanly. So the choice isn't stylistic, the question you must answer (“is my abstention rate drifting?”) has exactly one primitive that answers it.

The SDK calls (Python v3)

The OpenTelemetry-based SDK (get_client(), start_as_current_observation) attaches a score at whichever level you name. Verified against the Langfuse custom-scores docs.

# On an observation you already hold (a span):
span.score(name="abstained", value=1, data_type="BOOLEAN", comment="...")
span.score_trace(name="abstained", value=1, data_type="BOOLEAN")

# On whatever is currently active, no handle needed:
langfuse.score_current_span(name="faithfulness", value=4, data_type="NUMERIC")
langfuse.score_current_trace(name="abstained",   value=0, data_type="BOOLEAN")

# After the fact, by id (e.g. a human label arriving later):
langfuse.create_score(name="abstained", value=1, data_type="BOOLEAN",
                      trace_id=tid, observation_id=oid, comment="...")

data_type is one of NUMERIC (float), BOOLEAN (0/1), CATEGORICAL (string), TEXT (1–500 chars). Scores are batched. Call langfuse.flush() before the process exits or they never leave.

Where to attach it: batch vs production

Same verdict, different level, and the difference is the batch-vs-live distinction:

SettingOne trace is…Attach the score to…
Eval harness (--generate --trace)the whole run; each question is a child spanthe answer-question span → per-question grain: qspan.score(...)
Live appa single user requestthe trace → one verdict per request: score_current_trace(...)

What the score then buys you

  • The work queue (Control #6). Filter the trace list to abstained = 1 and you have the exact real-user questions your corpus couldn't answer. Each one is a doc to add or a chunk to fix, the gap closes over time instead of sitting constant.
  • The band, monitored. The mean of abstained over a window is the abstention rate, charted over time. Set an alert on the band edges.
  • Prod regressions CI can't see. Your CI gate only tests the fixed golden + trap set. A model swap that makes the system start answering things it shouldn't shows up as the live abstention rate dropping, on traffic you never wrote a test for.

Which verdicts are worth scoring

ScoreCost to emitType
abstainedFree: a sentinel string matchBOOLEAN
faithfulnessOne judge call per answerNUMERIC
retrieval_confidenceFree: top chunk's similarityNUMERIC

Same mechanism for all three: they differ only in what fills value. Start with the free one.

Defend it in one line

“I don't just trace latency and cost, I score answer quality onto the trace. Every request carries an abstained score, so in production I filter to the ones that declined, that's my queue of corpus gaps, and I watch the abstention rate as a band: a sudden drop means the model started answering things it shouldn't, on real traffic my CI golden set never covers. Faithfulness rides the same trace as a numeric score. Scores, not tags, because a tag can't average into a rate.”
