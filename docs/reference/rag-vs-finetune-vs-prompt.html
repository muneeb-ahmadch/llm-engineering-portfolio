RAG vs fine-tune vs prompt

Three levers, the one distinction that settles most interview questions, the cost trade, and the failure each one hides. Compressed from Lesson 08. Made to be reread the night before.

Three levers on three different parts of the system

ToolChangesTouched whenCost shape
PromptWhat you say, instructions + examples. Model untouched.Inference only. No training.Per-query tokens; few-shot examples lengthen every call.
RAGWhat the model can see, retrieved knowledge in the prompt. Weights untouched.Inference + an index you maintain.Per-query context tokens + retrieval infra. No training cost.
Fine-tuneWhat the model is, its default behaviour, via weight updates.Training run up front, then inference.Fixed training cost, then cheaper per query (shorter prompts).

Prompting changes what you say. RAG changes what the model can see. Fine-tuning changes what the model is.

The distinction that settles it: knowledge vs behaviour

GapSymptomReach forNot the other, because
Knowledge, doesn't know a fact“Answer about our private / fresh / changing docs.”RAG (or prompt if it fits)Fine-tuning is bad at new facts, and facts change → retrain forever.
Behaviour, knows, won't act right“Always this format / tone / abstain when unsure.” Prompt plateaus.Fine-tuning (after prompt's ceiling)RAG can't help: no missing fact, the form is wrong.

RAG fixes what the model doesn't know. Fine-tuning fixes how the model behaves.

Why fine-tuning is bad at facts (the citable part)

Fine-tuning makes patterns of response more likely: great for format, tone, task-shape. Teaching it a new fact means over-writing weights to memorise one string: models learn new facts slowly under fine-tuning, and learning them correlates with more hallucination nearby (the model generalises “confidently state things like this”). Paper to name: Gekhman et al., 2024, “Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?”. RAG sidesteps it: the fact lives in a retrievable, citable, swappable document, nothing memorised, nothing stale.

They compose: cheapest lever first

1. Prompt        →  always first. Free, instant. Exhaust it.
2. + RAG         →  gap is knowledge the model lacks (private / fresh / changing).
3. + Fine-tune   →  behaviour gap SURVIVES a good prompt AND task is stable + high-volume.

The mature answer names the ladder and where you stop: not one tool. Prompt+RAG is a correct stopping point until a measured behaviour gap justifies rung 3.

The cost trade

break-even volume  ≈  training_cost  /  (per-query saving from a shorter prompt)

RAG / prompt = pure per-query cost, context-dominated ($0.002174 in Lesson 07, input was 59% of the bill). Fine-tuning = fixed cost traded for lower variable cost. Pays off at high volume on a stable task; a bad deal for low volume or changing knowledge, you re-pay the training cost every time the facts move. (Fine-tune prices drift too: pull the current rate the day you need it.)

The failure each one hides

ToolHidden failure
PromptSilent ceiling: accuracy plateaus, no error, no signal you've hit the tool's limit.
RAGRetrieval miss → hallucination or abstention. Quality capped by retrieval; no parametric fallback on a private corpus.
Fine-tuneStale fact stated confidently, unattributable, no trace, no citation. You hear it from a user, not a metric.

Defend it in one line

“Prompting changes what I say, RAG changes what the model can see, fine-tuning changes what the model is. First question: is the gap knowledge or behaviour? Knowledge, especially private or changing, is RAG, because facts belong in an index I can update and cite, not weights that go stale. Behaviour is fine-tuning, but only after a prompt hits a measured ceiling and only if the task is stable and high-volume enough to earn back the training cost. My RAG system stops at prompt+retrieval on purpose, I haven't measured a behaviour gap that justifies the third rung.”
