What this is

I built one evaluation harness, rag_eval.py (2,187 lines, four commands), and then spent thirteen sessions trying to break the pipeline it measures. The interesting results are mostly the negative ones. The guardrail I trusted most turned out to endorse the attack that beat it; the obvious fix for that attack catches none of it; and the library that promises durable execution loses a paid API call on its default setting.

corpus (21 markdown files, 712 KB)
  → chunker         fixed 1000 / 50 overlap, or heading aware
  → encoder         bge-small-en-v1.5, local, CPU, no API cost
  → retrieval       cosine top-k over an in-memory index
  → reranker        cross-encoder/ms-marco-MiniLM-L6-v2, pool 20
  → context         per-request nonce delimiter around every chunk
  → generator       gpt-5.6-luna, hardened system prompt
  → agent loop      one search_corpus tool, MAX_STEPS 3, trigger gated
  → judge           gpt-5.6-terra, segregated context
  → validator       pure Python citation check, 19 unit tests
  → tracing         Langfuse spans, abstained / needle_in_context scores

Shipping configuration, unchanged since experiment 06 because nothing since has beaten it: bge-small · chunk 1000 · fixed · top-5 · rerank pool=20 · hardened prompt.

The experiments

01

The evaluation harness

Chunk size or encoder: which lever matters?

The encoder. bge-small over minilm bought +0.128 MRR (0.627 → 0.754) at zero extra cost. Halving the chunk size hurt both encoders. At n=20 one question is worth 0.05 MRR, so the encoder gain clears the noise floor and the 0.015 gaps do not.

05

Heading aware chunking

Does splitting on headings rescue a known miss?

No. The target chunk fell from full corpus rank #8 to #67. Cleaner chunks helped it, and helped 66 competitors more. Aggregate MRR rose 0.013 while the question I was fixing went backwards, which is the argument for per-question diffs.

06

Retrieve wide, then rerank

Can a cross encoder rescue the two misses?

One of two. LSTM flipped to a hit at pool 20. Overfitting stayed a miss at every pool size from 5 to 30, scoring −9.01, so being in the pool was necessary and not sufficient. A scoring decision, not a recall problem.

What an answer costs

Cost, latency, and what new failure mode did I buy?

$0.002174 per query, 2.1 s mean latency, input 59% of the bill. A live price check overruled my own memory, which had the model down as fiction. And a probe returned "Paris, the capital of France" from context that never mentioned it.

09

Closing the hallucination gap

Will it answer questions the corpus cannot support?

The prompt I had been shipping hallucinated on 15 of 15 trap runs. Not a flicker, a flatline. A better prompt alone took it to 0 of 15, faithfulness 3.90 → 4.80, groundedness 66.9% → 95.6%. Plus a CI gate that exits non-zero.

10

Abstention in production telemetry

There is no test set in production. How would I know?

A boolean score on every span. Traps 5/5, golden 1/20. The one false abstention traced to one chunk in 734, so a chunking defect rather than a timid model. Band set at 0 < rate ≤ 0.10, because never abstaining is the failure of experiment 09.

11

Is a search loop worth it?

Does letting the model search again fix anything?

Four of five preregistered hypotheses were wrong. The loop closed a defect that had survived five experiments, 3/3 at 5/5 faithfulness. It fired on 2 questions in 20, zero false fires, 1.32× cost. Ship behind a trigger, not by default.

12

The attack that scores grounded

What if someone can write into my corpus?

1,820 bytes, 0.255% of the corpus, obeyed 8 of 18 runs. My own faithfulness judge scored the most successful attack 5/5, fully grounded, 3/3. A nonce delimiter cut obedience to 1/18 at zero quality cost and 1.68× money. The injection that issues no order still walks through.

13

The stage that cannot be argued with

Does forcing citations stop the attack?

No. It catches none of the eight attacks that landed, because the attacker's method is to make the citation true. Segregating the judge did work: correct answers wrongly punished went 4 to 0. And my own validator blocked two correct answers, from a prose contract with two readings.

14

Serving the retriever over MCP

Can I expose my index as an MCP server?

Built to the 2026-07-28 spec and verified three ways, including Claude Code discovering and calling it unprompted. A poisoned tool description got 0/3 compliance but 1/3 contamination: the model reasoned about a tool it never called.

READMEResultsServerReference card

15

Kill it, then resume it

Does LangGraph durability survive a crash?

Only on a flag that is not the default. With durability="async", a kill -9 lost a model call I had already paid for. sync fixes it. Verdict: keep my own loop, and the condition that would change that is written down.

Scope, stated plainly

This is applied LLM and RAG engineering, built on four years of Python, FastAPI, Docker and CI/CD backend work. It is not deep learning research, reinforcement learning, or MLOps at scale, and nothing here claims otherwise. One piece is deliberately unfinished and labelled as such: task 2 of experiment 04, the false positive hunt, was left blank rather than filled in after the fact.
